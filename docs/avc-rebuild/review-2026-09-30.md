# AV/C worktree review — 2026-09-30

Reviewed `refactor/avc-stack` at `3a6582e2` against local `main`, the AV/C rebuild plan, Python graph prototype, fixtures, and available behavioral references. The worktree was clean before review. Phase stop instructions were ignored; deliberate deviations were judged by correctness and architectural fit. No implementation changes were made.

**Verdict: the codec direction is sound, but the branch needs corrections before merge.** There is a reproduced Duet vendor STATUS regression, an asynchronous accessor ownership defect, ignored generation binding, and incomplete production integration of the descriptor/graph work. Passing fixture tests currently overstate end-to-end coverage.

## Correctness findings

### 1. P1 — Duet vendor STATUS parsing loses the OUI

Location: `ASFWDriver/Audio/Protocols/Oxford/Apogee/ApogeeTransport.cpp:63`.

`RawVendorDependentOperands::Read()` in `Commands/GeneralCommands.hpp` removes the first three operand bytes (company ID). `VendorFcp::Send()` passes this stripped reply to `ApogeeVendorCommand::ParseStatusPayload()`, which still validates the complete OUI + PCM signature + command prefix. It therefore checks `50 43 4D` against `00 03 DB` and rejects valid Duet STATUS replies. All vendor state reads using this path are affected; CONTROL avoids this parser.

A standalone executable using the actual new generic decoder and existing Apogee codec reproduced:

```text
Apogee full operands parse=1; migrated vendor reply parse=0
```

Fix the codec contract consistently: ideally migrate the Apogee codec into the planned vendor extension and have it decode company ID and payload through an explicit reply type. Merely prepending the request OUI would lose validation of the actual response OUI. Add a test through `VendorFcp::Send`, rather than only testing the standalone vendor codec.

### 2. P1 — The second Audio descriptor read does not retain its accessor

Location: `ASFWDriver/Protocols/AVC/Audio/AudioSubunit.cpp:108`.

The identifier-read completion retains `accessor`, but the text-list completion does not. After the identifier completion returns and its read state is released, the local shared owner disappears. The text read remains pending with a raw `this` captured by `DescriptorAccessor::readNextChunk()`. When it receives a nonterminal chunk, it calls `readNextChunk()` on the destroyed accessor and reads its unit reference/subunit address: use-after-free.

This occurs for a chunked text database, such as the captured 3,895-byte Phase 88 child list, once traversal reaches it. The same ownership pattern exists in the music direct-read fallback at `Music/MusicSubunit.cpp:1012`; that callback also drops the retained unit. The main capability fallback at line 255 retains the unit but still drops the accessor. These music fallback patterns predate this branch, but remain unsafe in the revised path.

Keep the accessor and its unit owner alive for the entire asynchronous operation, including nested reads. A synchronous simulator completes everything before the enclosing callback releases its owners and cannot expose this bug. Test with deferred callbacks and at least two chunks under AddressSanitizer.

### 3. P1 — The real transport ignores the requested generation

Location: `ASFWDriver/Protocols/AVC/FCPTransport.cpp:899`.

`IAvcUnit::Submit(frame, generation, ...)` explicitly accepts a generation, but production `FCPTransport::Submit()` discards it. The underlying transport binds to `CurrentRoute()` when issuing the write. A command prepared against generation N can therefore be submitted after reset and transmitted in N+1, including CONTROL. Existing route-token checks protect a written attempt; they do not honor the caller's generation constraint. The simulator rejects this same request, so simulation and production disagree.

Carry the required generation through admission and queued write issuance; reject stale submissions with `kBusReset`. Also test a command queued before reset and dispatched after route revalidation. Keep explicit idempotent retry behavior distinct from silently rebinding a new stale CONTROL submission.

### 4. P2 — Audio descriptors bypass OPEN/CLOSE

Locations: `Audio/AudioSubunit.cpp:70`, `Audio/AudioSubunit.cpp:108`, `Descriptors/DescriptorAccessor.cpp:222`.

The new Audio discovery calls `readUnitIdentifier()`, which delegates directly to `readComplete()`, and uses another direct read for the text list. Neither descriptor gets an OPEN/CLOSE session. The captured fixture sequence and FFADO both open before reading. FFADO's behavioral path is in `/Volumes/SDExt/DEV/ASFireWire/references/libffado-2.5.0/src/libavc/descriptors/avc_descriptor.cpp:165` (OPEN), `:184` (READ), and `:274` (CLOSE).

Use the existing OPEN→READ→CLOSE operation for each descriptor. Preserve read failure while still closing a successfully opened descriptor. Make the simulator track open sessions and reject unopened reads unless a specific evidenced device quirk permits them.

### 5. P2 — Phase 88 text database traversal stops at the root

Location: `ASFWDriver/Protocols/AVC/Audio/AudioSubunit.cpp:89`.

The captured identifier advertises root list `0x1800`. That descriptor is a 35-byte list containing a child-list reference to `0x1801`; the actual 80 text entries are in the 3,895-byte child. The implementation reads the root and passes it to a text-object parser, then finishes successfully without following the child. Function-block names remain unresolved.

The Python prototype explicitly uses descriptor `101801`; the fixture documents the root/child distinction at `docs/avc-rebuild/fixtures/phase88_descriptors.md:30`. C++ parser tests manually supply the child bytes, so they bypass the faulty discovery logic.

Parse list/object references and follow the advertised child structure with bounds and loop protection. Avoid treating the particular IDs `0x1800`/`0x1801` as the generic discovery rule. Test identifier→root→child→resolved names through the asynchronous seam.

### 6. P2 — Malformed/truncated descriptors are accepted as successful models

Location: `ASFWDriver/Protocols/AVC/Descriptors/AudioSubunitDescriptor.cpp:55` and subsequent nested-length handling.

The parser does not enforce the descriptor's declared length. Missing required nested sections return an engaged optional, and oversized nested lengths are clamped to available data. This turns truncation into a valid empty/partial model. A standalone probe reproduced acceptance of this 10-byte fragment of a descriptor declaring 658 bytes:

```text
02 90 02 02 00 02 00 01 18 00
Truncated 658-byte identifier accepted from 10 bytes=1
```

The read accessor also calls a prematurely empty chunk successful, and the new READ operand decoder silently truncates `reportedLength` to the available payload. Together these layers can report a transport-truncated descriptor as successful discovery.

Validate outer and nested extents before parsing. Reject truncated declared fields, mismatched returned offsets, and premature empty chunks. If partial discovery is desired, represent it explicitly rather than as ordinary success. Add truncation/length/offset mutation tests; current Audio descriptor tests cover only happy-path captures.

### 7. P2 — The graph labels sync destinations as selectable clock sources

Location: `ASFWDriver/Protocols/AVC/Graph/AvcGraphBuilder.cpp:162`.

The builder emits destination plugs with a sync cluster directly into `clockSources`. These plugs are destinations for clock routing, not sources that have been confirmed selectable. The Python prototype keeps them as `syncDestPlug` plus `fedBy`; the Apple behavior notes require inquiries against candidate sources. The captured Phase 88 inquiries do not establish generic music-sync choices.

The builder also recognizes Audio clock selectors by English names and emits them with `subunitPlugId=0xFF`, losing the function-block address and selected/source alternatives. Unnamed or differently named selectors fail this heuristic.

Model sync destinations separately. Feed the pure builder discovered inquiry results and typed Audio selector identities/edges. Do not publish inferred options as validated clock sources.

### 8. P2 — Descriptor control hints become authoritative graph controls

Location: `ASFWDriver/Protocols/AVC/Graph/AvcGraphBuilder.cpp:186`.

The builder copies `masterControls` and `channelControls` directly from the descriptor, with no confirmed-control input or verification state. The plan explicitly requires STATUS confirmation because the Duet bitmap is wrong. Raw bitmap representations also differ between the captured devices; copying them into fields documented as common mute/volume bits does not establish normalized capabilities.

Keep raw advertised bitmaps as hints and build usable controls from measured STATUS results. Preserve function-block/channel/control identities and discovery errors. Add a test where the Duet hint disagrees with measured mute/volume availability.

## Architectural integration findings

These are incomplete planned outcomes, distinguished from new regressions.

1. **Audio-subunit discovery is unreachable on the primary devices.** `AVCUnit.cpp:263` retains the old rule that skips Audio whenever Music exists. Duet and Phase 88 both have Music and Audio. No Audio object is created, its identifier is not read, and the new user-client/MCP Audio descriptor endpoint cannot find it. The plain unit model lists the Audio subunit while the runtime list omits it. Remove this discovery suppression; device publication matching is a separate decision. Test full initialization of both fixtures and retrieval of both descriptors.

2. **The graph builder is isolated test code at present.** Repository search found its definitions and tests, but no production call. Publishers remain in `AVCDiscovery`; SIGNAL SOURCE results are not wired into graph options; the graph does not drive published geometry/maps/controls. The AV/C Report tab is absent. It is reasonable to stage this work, but Phase 4e should be described as a builder prototype until integrated.

3. **The plain-data unit model is not the authoritative model yet.** `model_.identity` is never populated; `SubunitModel::plugs` is initialized empty and not updated from capability queries; async plug counts remain default. Meanwhile runtime subunit objects own separate discovered information. Either populate this contract or narrow it so callers cannot mistake defaults for discovered zero counts.

4. **Legacy command construction remains live.** `AudioFunctionBlockCommand`, `StreamFormats/AVCSignalSourceCommand`, `MAudioSpecialCommand`, `AVCCommands`, `AVCCommand`, and `AVCUnit::SubmitCommand()` retain the old command/submitter route. The Phase-2 statement that every caller uses the seam and every frame is built only by the new codec directories is not true. Duet vendor framing also remains in the Oxford device area instead of `Extensions/Apogee`. Migrate remaining active commands, then remove superseded implementations.

5. **Phase 3 is an adapter, not a transport rewrite.** The original engine is retained with roughly 79 added lines implementing the seam. Keeping proven transport machinery can be a defensible scope adjustment. It still needs the requested-generation fix, unified response policy, and honest status wording. Blind BF→2F fallback is explicitly accepted in the updated phase document and is not a finding, although duplicating it in individual subunit methods weakens consistency across callers.

6. **Generic BeBoB still lacks per-direction/per-rate geometry.** It copies the first input formation into both directions, now while potentially selecting a different current rate. `SupportedRatesHz()` returns a union rather than valid duplex configurations. A device with asymmetric formations or fewer channels at higher rates cannot be represented correctly. Factory model delivery and generic publication remain unfinished Phase-5 work; do not infer broad compatibility from corrected rate tables alone.

7. **Error conversion remains inconsistent.** New BeBoB/M-Audio/Apogee callbacks frequently collapse every `AvcError` into `kIOReturnError`, while other callers use the new mapping. Timeout, reset, refusal, and busy distinctions are lost; `FCPStatus::kBusy` itself maps to generic transport error. Finish the common conversion contract.

## Python graph comparison

Ran `fixtures/graph_build.py` on both committed probe matrices and local descriptor fixtures. Both succeed. Phase 88 gives rates 32/44.1/48/88.2/96 kHz, the PCM permutation `[1,6,2,7,3,8,4,9,0,5]`, MIDI signals at `[10,10]`, 22 named function blocks, and explicit sync destination routing. Duet gives two PCM channels, music-plug channel names, and one unnamed feature block.

The C++ fixture tests agree on PCM permutations and primary names. Differences requiring explicit modeling/integration are SIGNAL SOURCE provenance, preserved cluster boundaries, MIDI positions/location detail, root/child text-list traversal, and clock-destination versus clock-source semantics. The richer per-plug channel names are supported by the Python prototype; using them is not inherently a plan violation. One CoreAudio stream per cluster remains a user decision, so it was not treated as mandatory.

The current tests duplicate large hexadecimal fixtures and manually inject selector names. Prefer loading the canonical fixtures and comparing normalized C++ results with prototype-derived expected graphs. This would make the tests sensitive to discovery and traversal, rather than only the selected parser inputs.
